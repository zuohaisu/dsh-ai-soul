# DSH 环境中的个体选择、切换与移除

2026-11-26，所有者已确认以下产品行为。适用于 [#426](https://github.com/zuohaisu/dsh-ai-soul/issues/426) 的首轮 DSH MVP；实际安装和用户验收结果另在 Issue 中记录。

## 用户选择一次，环境中的会话共同遵循

同一台机器上，同一 DSH 环境的各个窗口和会话共享当前个体选择。用户能从正常入口创建、选择、切换或移除个体，无需手改 profile。退出并重新打开 DSH 后保留环境选择。首轮在独立环境中使用显式启用的合成测试 profile。

选中 A 后，各会话中的用户可见输入和最终可见输出都作为 A 的经历保存，并保留各自的会话来源。Self Runtime 统一写入该测试个体的规范记录。宿主若创建 fork 或子 Agent，派生会话不会因此自动获得独立写权限。

## 何时沿用旧会话，何时开新会话

| 用户操作 | 对话和记忆的归属 |
|---|---|
| 继续或恢复 A 的原会话，期间没有切换个体 | 沿用会话开始时绑定的 A 的版本。即使 A 有新版，也允许这一轮及之后在原会话中继续使用原版本。 |
| 仍选中 A，显式开新会话 | 自动加载 A 当前最新的有效版本，无需额外操作。 |
| 从 A 切到 B | 已开始的一轮直到回复完成都归 A。从下一次输入起，所有窗口遵循新选择。回到承载 A 历史的旧窗口继续输入时，自动开启 B 的干净会话；A 的历史留在原会话。 |
| 移除当前个体 | 保留已开始一轮的原归属。从下一次输入起，旧窗口也开启普通 DSH 对话，无需绑定个体，不加载原个体的上下文，不向任何个体追加这段经历。移除只解除环境选择；用户以后可以选回 A 并继续使用已有记忆。 |

## 首轮用户验收

1. 在实际安装的 DSH 中通过用户入口选择 A，打开两个窗口，各输入一条不同的合成代号。完全退出后重开，确认仍选中 A，新会话能找回两条记录及各自来源。
2. 在 A 的一轮回复尚未完成时切换到 B。等回复结束，核对该轮输入和输出都归 A。在旧窗口输入第三条代号，核对新会话属于 B，未带入 A 的历史，第三条只进入 B 的记忆。
3. 移除 B，在同一窗口输入第四条代号，确认 DSH 可以继续对话，A 和 B 都没有新增这段经历。重新选回 A，确认其原有记忆仍在。
4. 单独核对版本边界：在 A 有新有效版本后恢复未切换个体的旧会话，仍使用原版本；再开新会话，自动采用新版。

以首次使用者能否独立完成操作验收入口。工程记录分别标明持久化回执、召回来源、请求送达与实际模型回答。脚本 provider 可以验证请求内容；若只做了脚本验证，真实模型回答和用户体验分别据实记录。
