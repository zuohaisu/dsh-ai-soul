# Live growth proof must include selectivity and next-turn use

Date: 2026-09-04

## Decision

A generic AI Soul selective-growth runtime proof is not established by showing only that a real interaction can eventually change persisted Soul State.

A valid live proof must establish both sides of the boundary:

1. **selectivity** — an ordinary interaction does not become durable Soul cognition merely because the Soul was present; and
2. **effective growth** — an eligible interaction can pass independent governance, persist a bounded mutation, refresh the same running process's Soul Context, and affect the next real model turn without the user restating the learned claim.

## Why

Presence, attention, interaction history, and long-term memory are distinct concerns. A system that promotes arbitrary interaction is not selective memory. A system that persists a claim but cannot make that claim available to the next real model turn has storage, not demonstrated cognitive continuity.

## Governance boundary

The proposer and human reviewer remain independent. Runtime evidence must preserve linkage from Experience through proposal/review/state commit/context assembly without giving the evidence collector any mutation authority.

## Evidence boundary

Automated integration tests, mocked DSH events, hand-edited Soul State, or renderer-only assertions remain useful engineering evidence but cannot replace a real TUI/Web run for Issue #27 acceptance criterion 6.

This decision is generic and does not depend on Samuel Experiment 001 or the Haisu Test.
