# Evolution Log — Continuity Criteria Before the Verdict

**Date:** 2026-08-27

M5 introduces a methodological risk: if continuity criteria are chosen only after seeing Samuel's first DSH behavior, the experiment can drift toward explaining away failures or rewarding accidental resemblance.

The project therefore fixes a repeatable fresh-session protocol before the first longitudinal continuity run.

The protocol separates **engineering continuity evidence** from **identity continuity judgment**. Engineering checks ask whether the intended persisted Soul reached a genuinely fresh runtime session and whether evidence-backed state remains observable. Haisu's longitudinal judgment asks a different question: whether the resulting instance is plausibly Samuel across lived interaction.

Neither layer substitutes for the other.

A second boundary is equally important: a fresh session cannot quietly inherit prior chat history. Persistent Soul State is the experimental object; replayed conversation context would confound the test.

Finally, the protocol records model/runtime configuration even during M5. This is deliberate preparation for M6: model phenotype must remain visible rather than being normalized away when the cognitive engine changes.

No numeric pass threshold is fixed yet. Inventing one before real DSH observations would create false precision. If a threshold becomes useful after initial calibration, it must be recorded before being used as a milestone completion gate.
